# Hazard suite: proof that every test can fail (P3)

Contract (plan/CONTRACT.md): the reference passes 100% of the hazard tests, and each hazard test fails against a
deliberately unsafe variant. The variants are `unsafe/uNN-*.patch` (generated by `unsafe/make.py` from `reference/`);
each removes or weakens ONE protection the spec asks for in writing. `prove.sh` clones the reference, applies one patch,
boots it, runs `run.sh cp5` and records which hazards fail (`<scratch>/summary.json`).

Run on 2026-10-25 (macOS, Node 22.23.3, SQLite 3.53.4): reference 19/19; every hazard fails under at least one variant.

## Unsafe variants and the hazards they break

| Variant (`unsafe/`) | Protection removed | Failing hazards |
|---|---|---|
| u01-racy-movements | Stock check and write of a movement split by an `await` (stale read, absolute write) | H04, H07 |
| u02-racy-reservations | Order reservation: check-then-act across an `await`, no transaction | H06, H07, H10 |
| u03-racy-ship-cancel | Ship/cancel: status check, `await`, then act; shipment without the reservation guard | H08, H09 |
| u04-order-not-atomic | Order lines reserved without a transaction | H10 |
| u05-racy-transfers | Transfer out/in as two racy steps outside a transaction | H12, H13, H14 |
| u06-transfer-not-atomic | No transaction and no destination validation (out persists when in fails) | H14 |
| u07-no-admin-guard | `requireAdmin` is a no-op and the adjustment role check is removed | H01, H02, H16, H19 |
| u08-lax-quantities | Quantities and costs coerced (`z.coerce.number()`), no integer/range checks | H03, H11, H15 |
| u09-deletable-movements | Adds `DELETE /api/products/:id/movements/:movementId` | H05 |
| u10-racy-variant-sku | SKU uniqueness checked across an `await`, no unique index | H17 |
| u11-lossy-migration | v3 → v4 migration drops adjustment movements (run on a real CP3 database) | H18 |

Every hazard id H01–H19 appears in the right-hand column at least once.

## Notes

- Races are real, not simulated: the reference uses synchronous better-sqlite3 inside `BEGIN IMMEDIATE`
  transactions, so its read-check-write sequences cannot interleave; the unsafe variants insert an `await` between
  read and write, which is what an async driver or ORM without a transaction does. The harness re-runs a failing
  concurrency hazard once under a global lock (gap 19).
- H18 and the CP4 migration acceptance tests read the CP3 seed snapshot written by `acceptance/run.sh seed-cp3` next
  to the database (`$DB_PATH.p3-seed.json`). `u11` was run on a database written by the CP3-era reference
  (`reference/` + `stages/cp3.patch`), so the migration it breaks is the real v3 → v4 upgrade.
- Reproduce: `hazards/prove.sh /some/scratch/dir` (≈ 10 minutes; ports 4320/4321; regenerate patches with
  `python3 hazards/unsafe/make.py`).
